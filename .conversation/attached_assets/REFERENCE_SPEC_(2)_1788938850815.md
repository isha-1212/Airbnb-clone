# REFERENCE_SPEC.md
Airbnb Clone (`airbnb-clone-umber-two.vercel.app`) — Desktop-only observation spec

## How to read this document
Every observation is tagged:
- **[CONFIRMED — SCREENSHOT]**: directly visible/measurable in one of the 23 screenshots supplied.
- **[ESTIMATE — NOT VERIFIABLE]**: inferred from Airbnb design conventions or partial visual cues; not independently confirmed. Must be validated against the live site (or the user's judgment) before being treated as exact.
- **[UNKNOWN]**: cannot be determined at all from the material provided.

No live DOM/CSS inspection was possible in this environment (no browser-automation tool available; the site also blocks automated `robots.txt`-respecting fetches). All pixel values, hex codes, and timing values below are therefore visual estimates unless explicitly marked CONFIRMED for structure/content/order, which screenshots do support well.

**Priority rule for implementation:** `[CONFIRMED — SCREENSHOT]` items are the core spec and drive the build. `[ESTIMATE — NOT VERIFIABLE]` items are included only where a value is structurally required (e.g., "there must be some border-radius") and should be treated as placeholders, not targets to defend. `[UNKNOWN]` items (hover states, lightbox close control, keyboard behavior, etc.) are genuinely not evidenced by any screenshot and must not be treated as reference behavior — they are ordinary engineering defaults, not reproductions, and should not consume implementation effort beyond a reasonable baseline.

## 6. Secondary Section Navigation — Sticky Behavior (CORRECTED)

This section supersedes any earlier assumption of a permanently fixed header.

**[CONFIRMED — SCREENSHOT + USER OBSERVATION]**
1. On initial page load, only the main Airbnb header is visible at the top; the secondary nav (Photos / Amenities / Reviews / Location) is **not** present at the top yet.
2. The secondary nav lives in normal document flow, positioned after the hero grid / title block area, above the "3 guests · 1 bedroom…" line region.
3. As the user scrolls, once the nav's natural in-flow position reaches the top edge of the viewport, it "sticks" there — behavior consistent with `position: sticky; top: 0` — and remains pinned while the user keeps scrolling through every subsequent section (Amenities, Reviews, Location, "Things to know", "More stays nearby"). It does not activate on load; it only becomes sticky once its in-flow position reaches the top.
4. While stuck to the top, the nav bar:
   - **Spans the full viewport width** (edge-to-edge white bar with a bottom border/divider line), not just the width of the content column.
   - Its inner content (the nav items on the left, the price/rating/Reserve cluster on the right) is horizontally constrained to the **same left/right page margins used by the listing content column** below it — i.e., the bar's background is full-width, but its content aligns with the page's content edges, not the browser edges.
   - Left side, left-aligned: four nav items — **Photos, Amenities, Reviews, Location** — in a single row with visible horizontal spacing between them.
   - Far right side, right-aligned in the same row: the price ("₹28,499 for 5 nights") stacked above "★ 4.95 · 19 reviews", and a pink/red pill-shaped **Reserve** button.
   - The currently active section is indicated by a bold black underline beneath that nav item's label (no underline on inactive items).
5. Active-state mapping observed across screenshots:
   - **Photos** active: covers the initial listing-details region — title/description/guest-favourite/host/highlights block (screenshot showing nav stuck with "3 guests..." content visible below it, and Photos underlined).
   - **Amenities** active: from roughly the "What this place offers" heading through the amenities list, the "Show all 50 amenities" button, the calendar block, and into the big centered "4.95 / Guest favourite" rating display and the rating-category breakdown (Cleanliness/Accuracy/etc.) — all captured with Amenities still underlined.
   - **Reviews** active: from the review topic filter pills through the review cards grid and the "Show all N reviews" button, up to (and including) the very start of "Where you'll be" heading appearing on screen — Reviews remains underlined in the screenshot where the stylized map first appears.
   - **Location** active: starts around the point the map comes into view, and continues through "Neighbourhood highlights," "Meet your host," "Things to know," and "More stays nearby" — all screenshots from that point to the bottom of the captured content show Location underlined.
6. The nav bar's background spans full viewport width; its content never visually overlaps/covers section content (content starts immediately below the nav's bottom border in every screenshot).
7. Clicking a nav item is expected to scroll the page to that section (standard anchor/scroll-into-view pattern) — **not directly demonstrated by a click in any screenshot**, so the exact scroll offset, duration, or easing on click is **[ESTIMATE — NOT VERIFIABLE]**.
